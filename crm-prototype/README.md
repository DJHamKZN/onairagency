# ON AIR CRM — локальный прототип пресейла

Самостоятельный прототип внутренней CRM для пути «входящий запрос → подтверждённая передача проекта в работу».
Цель — проверить процесс, удобство и полноту решений на **вымышленных** примерах и сравнить с текущей CRM.

> **Это не готовая к эксплуатации система.** Синтетические данные, только локальный запуск (127.0.0.1), без HTTPS.
> AI, транскрибация, почта, Drive, календарь, подписание и платежи **не подключены**. Сервер проверяет роли
> и переходы, но не проходил проверку безопасности. Не вносите реальные клиентские данные, пароли и ключи.

Существующий сайт агентства в корне репозитория (`index.html`, `js/`, `css/`) не изменялся. Текущая CRM не трогалась.

## Быстрый старт

Требуется **Node.js ≥ 22.13** (используется встроенный `node:sqlite`; проверено на Node 22.22.0). Других системных зависимостей нет.

```bash
cd crm-prototype
npm ci                      # установка зафиксированных версий
cp .env.example .env        # при желании поменяйте DEMO_USER_PASSWORD
npm run build               # сборка интерфейса (esbuild) в dist/
npm start                   # сервер на http://127.0.0.1:5174
```

При первом запуске база пуста — сервер загружает синтетические кейсы. Учётные записи (вымышленные роли):

| Логин | Роли | Назначение в демо |
|---|---|---|
| `owner` | Владелец + Проджект пресейла (совмещение, роль выбирается в шапке) | всё; кейс C ведёт как PM |
| `pm` | Проджект пресейла | кейсы A и B |
| `pm2` | Проджект пресейла | «Площадка Пример» (для проверки изоляции) |
| `lead` | Ведущий специалист + Специалист | диагностика, проверка доказательств |
| `spec` | Специалист | своя оценка |
| `rpm` | Принимающий проджект | приёмка пакета |

Пароль — значение `DEMO_USER_PASSWORD` из `.env`. Если переменная не задана, сервер генерирует случайный пароль и печатает его в консоль.

Разработка: `npm run dev:server` (перезапуск при изменениях) и `npm run dev:client` (пересборка интерфейса).

## Проверки

```bash
npm run typecheck   # TypeScript, строгий режим
npm test            # 73 теста: доменная логика + реальный HTTP-сервер на временной БД (node:test)
npm run test:e2e    # 14 браузерных проверок: 7 сценариев × (1440 px и 390 px), Playwright + Chromium
npm run restore-check -- <backup.json>   # восстановление копии в отдельную чистую базу и сверка
```

Команда `test:e2e` рассчитана на shell Linux/macOS (в `playwright.config.ts` используются `rm -rf` и переменные окружения в строке). Нужен Chromium для Playwright 1.56 (`npx playwright install chromium`, если его нет). Скриншоты прогона — в `docs/screenshots/`.

## Структура

```
crm-prototype/
├── src/domain/          чистые функции и типы (без ввода-вывода; используются и сервером, и интерфейсом)
│   ├── types.ts           сущности: Company, Contact, Opportunity и вложенные записи
│   ├── money.ts           целые копейки, half-up, форматирование
│   ├── economics.ts       C, P = C/(1−c−m), комиссия, остаток, полнота расчёта
│   ├── approval.ts        неизменяемый снимок существенных условий и различия по категориям
│   ├── commands.ts        все действия над возможностью: (агрегат, команда, контекст) → (агрегат, события)
│   ├── stages.ts          5 рабочих стадий, условия переходов
│   ├── launch.ts          пакет передачи, хэш пакета, причины блокировки запуска
│   ├── audit.ts           модули, путь заявки, проверка доказательств
│   ├── demoParser.ts      «демо-разбор» на правилах (НЕ AI)
│   ├── permissions.ts     матрица ролей, серверные представления с вырезанием данных
│   ├── clientExport.ts    клиентский экспорт по разрешённому списку полей
│   ├── backup.ts          формат резервной копии и её валидация (zod + проверка ссылок)
│   └── hash.ts            стабильная сериализация + SHA-256
├── server/              локальный HTTP-сервер (node:http + node:sqlite)
│   ├── db.ts              миграции, append-only триггеры
│   ├── repo.ts            хранение, optimistic concurrency, журнал, резервные копии
│   ├── service.ts         права → версия → доменная команда → атомарное сохранение с журналом
│   ├── app.ts             маршруты API, сессии, экспорт, импорт с подтверждением
│   ├── auth.ts            scrypt, сессии (в БД — только хэш токена), лимит попыток входа
│   ├── docs.ts            DOCX (docx) и PDF (pdf-lib) — только локальный экспорт
│   ├── seed.ts            синтетические кейсы через те же команды, что и UI
│   └── main.ts, cli.ts    запуск, seed, restore-check
├── src/client/          интерфейс (React 19, без UI-фреймворков)
├── tests/               node:test — домен и API
├── e2e/                 Playwright — сценарии в браузере на 1440 и 390 px
├── scripts/build.mjs    сборка интерфейса esbuild
└── docs/                модель данных, API, приёмка, матрица, резервные копии, вопросы, сравнение
```

Поток модулей: **UI → HTTP API → Service (роль, назначение, версия) → domain/commands (чистая функция) → Repo (транзакция: агрегат + журнал + снимки)**.

## Версии зависимостей (зафиксированы в package.json / package-lock.json)

Runtime: react 19.1.1, react-dom 19.1.1, zod 3.25.76, docx 9.5.1, pdf-lib 1.17.1, @pdf-lib/fontkit 1.1.1.
Dev: typescript 5.9.3, tsx 4.20.5, esbuild 0.25.10, @playwright/test 1.56.1, @types/*. `npm audit`: 0 уязвимостей на момент сборки.

Почему такой стек: TypeScript во всех слоях; одна команда запуска без внешней БД и без платных сервисов; SQLite-файл легко
скопировать или удалить; доменная логика — чистые функции, переносимые на любой сервер. Vite изначально планировался,
но в этой среде его production-сборка зависала, поэтому интерфейс собирается напрямую esbuild (быстрее и меньше зависимостей).

## Допущения

- Все компании, роли, тексты и суммы вымышлены; суммы — «условные рубли».
- Ставки (2 500 и 2 000 у. р./ч), целевая маржа 30 %, комиссия 10 % — **тестовые значения**, не утверждённые владельцем; так и подписаны в интерфейсе.
- Налоговая модель в кейсе C — демо-допущение «учтено в ставках». Прототип налоговые ставки не подставляет.
- Цена по формуле округляется вверх до целого рубля (правило переключаемое; утверждает владелец).
- «Отправка КП» и «Оплачено» — ручные отметки о событиях вне системы.
- Логотип не используется: официальный файл не предоставлен; в шапке — текстовый заголовок «ON AIR CRM».
