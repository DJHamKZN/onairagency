## Воспроизводимый сценарий сравнения

**Условия.** Текущая CRM — только отдельная копия или тестовая среда. Рабочую production-базу не трогать, тестовых клиентов в ней не создавать.
Если тестовой среды нет: заполнить только колонку прототипа, для текущей CRM оставить read-only наблюдения, а сохранение, права,
конфликты и другие изменяющие проверки пометить «не проверено».

**Подготовка прототипа:** `npm start`, «Данные и настройки → Очистить демо-данные» перед каждым прогоном.

**Кейсы и шаги (одинаковые для обеих систем):**

1. **Линия Плюс (A):** создать запрос → вставить «Демо-заметку 1» (`server/seed.ts`, `DEMO_SOURCES.A1`) → разобрать сведения →
   выбрать маршрут A → добавить работу «Лендинг» с объёмом и приёмкой → расчёт → утверждение → фиксация отправки v1.
2. **Маяк Сервис (B):** создать запрос → вставить расшифровку B1 → короткая внешняя проверка (путь заявки, 2–3 модуля) →
   предложить платную диагностику → убедиться, что внедрение осталось открытым.
3. **Контур Образец (C):** две заметки C1 и C2 → решить противоречие дат → расчёт C = 90 000, c = 10 %, m = 30 %,
   внешний бюджет 40 000 → утвердить 150 000 → скидка до 140 000 → проверить снятие утверждения и причину → новая
   отправка, принятие → пакет запуска → приёмка проджектом → разрешение владельца.

**Что фиксировать (измеряется при прогоне, заранее не заполняется):**

| Метрика | Кейс | Текущая CRM | Прототип |
|---|---|---|---|
| Время от открытия до записи следующего шага, мин | A / B / C | | |
| Число обязательных полей до первого сохранения | A / B / C | | |
| Число ручных действий (клики + вводы) до отправки КП | A / C | | |
| Сведения, введённые повторно (перечень) | A / B / C | | |
| Нерешённые противоречия на момент отправки | C | | |
| Ошибки расчёта (отклонение от 150 000 / 15 000 / 45 000 и 140 000 / 36 000) | C | | |
| Потеря версии (можно ли увидеть отправленную v1 после изменений) | C | | |
| Забытые условия передачи (пункты, не замеченные системой) | C | | |
| Понятна ли причина блокировки (да / частично / нет + цитата сообщения) | A / C | | |

Время засекать секундомером одним и тем же человеком; клики считать по записи экрана. Три кейса находят дефекты,
но не доказывают рост конверсии или прибыли.

## Предложение по решению после прогона

Решение принимать **после** заполнения таблицы. Предварительные критерии:

- **Оставить текущую основу и перенести удачные решения**, если в тестовой копии подтвердятся серверные согласования, сброс
  утверждения и concurrency, а разница сводится к интерфейсу: перенести постепенный сбор, очередь изменений, вкладку ≠ стадия,
  утверждение до отправки, фильтры списка, статусы «частично».
- **Доработать альтернативу**, если в текущей CRM подтвердятся потери версий, неснятые утверждения или отсутствие серверных
  ограничений — их трудно добавить поверх общей модели доступа.
- **Пока не выбирать**, если тестовой копии нет. Красивый экран не компенсирует потерю истории, данных или серверных ограничений.

Моя текущая оценка без прогона: **пока не выбирать**.

## Известные дефекты и ограничения прототипа

1. Конкурентность — на уровне всей возможности: двое, правящие разные разделы одной карточки, получат конфликт 409 (без потери данных, но с повторным вводом).
2. Вложенные сущности в JSON агрегата, без внешних ключей SQL.
3. (Исправлено 07.10) Разовые и ежемесячные работы считаются раздельно. Скидка применяется к одной из частей; рассрочки и сезонности нет.
4. Варианты КП (несколько пакетов на выбор) не реализованы — сознательно, но реального выбора объёма тоже не поддержать.
5. Разбор по ключевым словам узкий: даты только вида «20 ноября 2026», ключевые слова фиксированы; возможны и пропуски, и ложные срабатывания. Это не замена разбору человеком.
6. В интерфейсе нет форм редактирования существующей находки и работы (команды `updateFinding`, `updateWorkItem` есть в API и тестах); работу можно удалить и добавить заново.
16. (Исправлено 07.10) Веб-артефакт обновлён текущей сборкой; ограничения браузерного режима сохраняются.
18. (Исправлено 07.10) Данные прежней версии в браузере показывали в «Запуске» пустые названия проверок и «undefined», а при отметках «выполнено» отбрасывались целиком. Добавлена миграция схемы 1 → 2 (см. ACCEPTANCE).
17. Конфликт версий определяется на уровне всей карточки: двое, правящие разные разделы, получат конфликт; данные не теряются, действие можно повторить.
7. Сущность `Contact` есть в модели и резервной копии, но UI для контактов нет — контакт и роль в решении хранятся как сведение «Контакт и роль в решении».
8. Справочник ставок в настройках хранится, но в расчёт не подставляется — ставки вводит владелец в строках.
9. КП и пакет передачи экспортируются только в DOCX; PDF есть только для выжимки аудита, вёрстка PDF простая (без таблиц).
10. Ограничение попыток входа хранится в памяти процесса и сбрасывается при перезапуске.
11. (Исправлено 07.10) Комплект документов аудита сохраняется снимком с номером и датой.
12. Сроки демо-шагов зафиксированы на октябрь 2026 и со временем будут выглядеть просроченными.
13. Очистка демо-данных не удаляет демо-компанию, если на неё ссылается не-демо возможность; повторное наполнение создаст компанию с тем же названием.
14. Production-сборка через Vite в этой среде зависала; сборка переведена на esbuild. Dev-сервера с горячей заменой нет — `npm run dev:client` пересобирает файлы, страницу нужно обновить.
15. Доступность проверена частично (см. ACCEPTANCE, критерий 20).
