# Локальный API (реализован и проверен тестами `tests/api.test.ts`)

Сервер слушает только `127.0.0.1` (при другом `HOST` отказывается запускаться). Все ответы — JSON, кроме файлов экспорта.

**Защита запросов:** сессионная cookie `HttpOnly; SameSite=Strict` (8 ч, в БД — только хэш токена).
Каждый изменяющий запрос обязан иметь заголовок `X-Requested-With: onair-crm`, иначе 403.
Роль действия — роль сессии (`POST /api/session/role`), допустимая только из ролей пользователя.

| Метод и путь | Кто | Описание |
|---|---|---|
| `POST /api/login` `{login,password}` | все | вход; 10 неудачных попыток → блок на 15 мин |
| `POST /api/logout` | вошедший | |
| `GET /api/me` | вошедший | пользователь и текущая роль |
| `POST /api/session/role` `{role}` | вошедший | смена роли действия (403 если роль не назначена) |
| `GET /api/team`, `GET/POST /api/companies` | вошедший / владелец, PM | |
| `GET /api/opportunities` | по ролям | только доступные (владелец — все, PM — назначенные, специалист — где назначен, принимающий PM — на стадии запуска) |
| `POST /api/opportunities` | владелец, PM | создание; 422 с перечнем недостающего |
| `GET /api/opportunities/:id` | по ролям | **серверное** представление: для не-владельцев ставки, себестоимость, комиссия, маржа удалены; чужой ID → 404 |
| `POST /api/opportunities/:id/commands` `{command:{type,payload}, expectedVersion}` | по матрице `COMMAND_ROLES` | 200 новое представление · 403 роль · 404 недоступно · 409 версия устарела · 422 доменное правило (`message`, `missing[]`, `field`) |
| `GET /api/opportunities/:id/history` | по ролям | журнал; экономические значения скрыты для ролей без доступа |
| `GET …/export/proposal/:pid?format=json\|docx` | владелец, PM | клиентский КП по allowlist; генерация пишется в журнал, статус не меняет |
| `GET …/export/audit/client_brief_pdf\|client_detailed_docx\|client_json` | владелец, PM, ведущий | клиентский аудит: только проверенные находки + пробелы |
| `GET …/export/audit/internal_docx` | владелец (или PM с разрешением) | внутренний документ |
| `GET /api/dashboard`, `/api/findings`, `/api/approvals` | по ролям | обзор, реестр находок, журнал утверждений (специалисту — 403) |
| `GET/PUT /api/settings` | чтение — все (урезанно), запись — владелец | с версией |
| `GET /api/admin/backup` | владелец | резервная копия JSON |
| `POST /api/admin/import/preview` (тело — JSON-текст) | владелец | проверка без изменений; токен подтверждения на 10 мин |
| `POST /api/admin/import/confirm` `{token, confirmText:"ЗАМЕНИТЬ БАЗУ"}` | владелец | восстановление в новый файл, сверка, замена; прежний файл сохраняется |
| `POST /api/admin/reset-demo` `{confirmText:"ОЧИСТИТЬ ДЕМО"}` | владелец | удаляет только `is_demo` записи и наполняет заново |

Список команд и их полезная нагрузка — тип `Command` в `src/domain/commands.ts`; права — `COMMAND_ROLES` в `src/domain/permissions.ts`.
Дополнительные полевые проверки внутри команд: ставки — только владелец; специалист — только часы своей строки и свои находки;
приёмка пакета — только назначенный принимающий PM; обход ограничения стадии — только владелец, с причиной и флагом `override` в журнале.

**Ограничение:** детальная схема каждого payload проверяется доменными функциями (обязательные поля, типы чисел, отрицательные значения), а не отдельной zod-схемой на каждую команду.
